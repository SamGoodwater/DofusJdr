# Entity views — IA

> Système d'affichage des entités.

## Fichiers pivots

- `resources/js/Utils/entity/resolveEntityViewComponent.js`
- `resources/js/Pages/Molecules/entity/<type>/`
- `resources/js/Pages/Organismes/entity/EntityEditForm.vue`
- Action `view-dofusdb` → store Pinia `dofusDbReference` + `DofusDbReferencePanel` (layout Main)
- Favoris BDD → `useFavoriteEntityIds` + `api.favorites.*` ; UI `FavoritesModal` / page `/favoris`
- Infobulle **prix** : `buildKamasPriceTooltip` (full item/consommable + descriptors). Ressource = « Prix proposé par Dofus ». Item/consommable = calculé + formule ; mention si `price_custom` ≠ 0. Bouton actualiser (vue full, `can.update`, hors consommable `playable`) → POST `recalculate-price`. Édition : `ItemPriceEditSection` (item et consommable ; `allowRecalculate` false si jouable). Masse : dashboard `/admin/content` (`entities:recalculate-prices`, skip consommables jouables).
- Tableau objets (vue Colonnes) : image + nom + niveau + type + rareté + **bonus** (`items.effect` Krosmoz, chips ; `items.bonus` = brut Dofus) ; description / résumé / prix masqués ; filtre **état** = pastilles à droite de « Filtres » (foncé / teinte d’état via `getEntityStateChipClass`), défaut `playable` (comme les autres catalogues).
- Tooltips d’en-tête : `TanStackTableHeader` lit `column.tooltip` (`getEntityFieldTooltip` depuis descriptors).
- Badges type / rareté / niveau (ressources, équipements, consommables) : `EntityFieldTooltip` (description courte hors tableau `characteristics` ; helper + limites min/max si caractéristique BDD). `FIELD_HELPERS` dans `SharedConstants`.
- Share Inertia `characteristics` : `limit_min` / `limit_max` (entiers figés du pivot, pas les formules).
- Rareté (items, ressources, consommables) : libellés uniques 0–5 (Commun … Unique) via `Resource::RARITY` / `RARITY_GRADIENT` ; les filtres tableau reprennent la même liste.
- Tableaux d’entités : filtres auto-appliqués (server-side), `filters[k][]` (listes) ou `filters[k][min]` / `[max]` (plages), tri via `sort.field` / alias SQL, recherche `search=` ou nom côté client. Charte : **niveau** = slider dual natif (`RangeDualCore`, bornes catalogue) ; **état** = pastilles à point à droite de « Filtres » (défaut `playable` ; conditions : hors `raw`) ; types / rareté = menu select compact (`resolveTableFilterLayout`, défaut `menu`) ; stats combat via **Ajouter un filtre** (icône + couleur `filterCharacteristicMeta`) ; bonus items/panoplies = sélecteur de caractéristique puis min/max (`picked-range`) ; **pas d’input texte**. Défauts de colonnes (`defaultByLabel`) seulement quand les options de **ce** filtre arrivent ; `initialFilterValues` fusionne par contenu, sans réécrire la saisie en cours.
- Catalogue objets / ressources / consommables / monstres / sorts / panoplies : filtre Type ou Race **sans valeur par défaut** (Tous). Le flag admin `show_in_catalog` reste (registre des types) ; `defaultByCatalog` n’est plus posé sur ces descriptors. Les listes `GAMEPLAY_*` restent un repli pour `resolveFilterDefaultValue` si un filtre le redemande.
- Action `refresh` (« Sources ») : modal unique DofusDB | conversion IA | JSON (`EntitySourceModal`). Onglets DaisyUI `tabs-box` : **Conversion DofusDB** (algo, case **Récupérer l’image**), **Conversion IA** (admin) et **JSON** (admin, collage / fichier, sans LLM). DofusDB si scrapable + `update` ; IA/JSON si admin et type convertible. Après écriture : tableau avant/après (`EntityUpdateDiffView`) — clic cellule / en-tête pour garder l’ancienne ou la nouvelle valeur ; **Enregistrer** applique le mix ; **Rétablir** (ou fermer) annule. Pas de seconde icône IA.
- Catalogue états : filtre État précoché hors Brut (`CONDITION_CATALOG_STATE_DEFAULT`) ; API exclut `raw` si le filtre est absent. Dissipable = interrupteur boolean. Flags mécaniques en chips (`ConditionMechanicalFlags`) + colonne Effets. Éditeur d’effets : picker hors `raw` (canons JDR).
- Notes de règles (rappels courts) : sorts via `spellTypeRuleNotes` + `SpellUsageBlock` (`data-cy="spell-rule-notes"`) ; consommables / objets via `consumableRuleNotes` / `itemRuleNotes` + `EntityRuleNotes` (cumul ; soins et respec « Hors combat uniquement » si l’effet le dit ; parchemin de caractéristique = plancher de création ; durée jusqu’au repos long si l’effet le dit). Toutes les vues (minimal compact+déployé, line, full).
- Overlay sort depuis un monstre : payload `effect_usages_chips` + `SpellViewMinimal` étendu (actions à droite du titre, overflow dropdown). Eager-load `visibleToUser` (brouillon masqué). Fetch `whitelist[]=` seulement si les chips manquent.
- Overlay fiche minimale (`EntityViewTextLink`, recherche, kref CMS) : panneau `chromeless` — pas de seconde boîte tooltip autour de la carte. Les krefs d’entité dans un texte de section (`ReferenceInlineNodeView`) hydratent la même `*ViewMinimal` étendue (`loadKrefEntityMinimalOverlay`). `displayMode: extended` n’affiche que le slot expanded (hauteur du contenu). Actions sans fond. Carte `hover` : reste déployée tant qu’un overlay issu d’elle est ouvert (`entityMinimalCardOverlayHold` **et** `[data-dropdown-open]`) — tooltips `OverlayTrigger` **et** menus `Dropdown` (état, ⋮), tous deux téléportés hors de la carte. Tooltips / popovers d’entités : une seule surface (`OverlayTrigger` n’empile plus `tooltip-floating-surface` si le contenu ou `panelClass` a déjà le chrome ; sorts `SpellUsageCharacteristicTooltipPanel` / chips d’effets en `glass=false`).
- Sorts / capacités Minimal et Line : le glass (`EntityMinimalCard` `surfaceStyle`) garde le fond du thème ; l’élément se lit en **halo** (`entity-element-ring` : lueur intérieure large + lueur extérieure légère + filet 1px à 20 % d’opacité ; `--element-border-color`, dégradé `--element-border-image` si plusieurs primaires). Sans élément, bordure thème. Couleurs : jetons DaisyUI (`--color-shop-700` Terre, `--color-error-600` Feu, etc.).
- Tableaux d’entités : ouverture en vue **minimal** (prefs v4 : l’ancien défaut `line` est migré ; `table` conservé). Grille : la cellule passe au-dessus des voisines au survol / carte déployée (`z-index`, pas `isolate`) pour que l’overlay ne passe pas sous la carte du dessous.
- Minimal déployé (consommables, ressources, équipements) : description complète (pas de `line-clamp`).
- Vue Full / `EntityPropertyDisplay` : champs longs (`description`, textarea…) avec `wrapValue` — valeur entière, pas de `truncate` (surtout mobile).
- `EntityViewHeader` (full + compact / modal) : sous `md`, **titre puis image puis infos** ; dès `md`, image à gauche. Même logique sur les ViewFull sans header partagé (trait, état, scénario, boutique).
- Barre d’actions (`EntityActions`) : raccourcis inline mesurés (`useHorizontalOverflowCount`, `measureFlexRowLeftoverPx`) ; ce qui ne tient pas reste dans le « ⋮ ».
- Monstres : sorts **et** équipements (`MonsterCreatureSpellsList` / `MonsterCreatureItemsList`) si la créature en a
- **PNJ** : mêmes listes sorts/équipements (prop `creature`) ; Full = `EntityViewHeader` + lieu / rôle / langues / traits / récit / sorts (empty state) / stuff / panoplies / boutique + pied `read_level`/`write_level` ; Line = classe, rôle, taille, hostilité, lieu ; Minimal (défaut `extended`) = même carte que Monster (taille, hostilité, description, langues, traits, caracs, compétences, sorts/items) + rôle/lieu/classe ; vue texte = nom + langues inline ; Index server-side comme les monstres. Conversion IA via le modal **Sources** (admin). Descriptors : `npc_role`, `size` enum 0–5, `creature_location`, colonnes combat créature (`creature_life`/`pa`/`hostility`…), placeholder « Rechercher un PNJ ».
- **Panoplies** : pas d’image propre — vignette = images des équipements (sinon initiales du nom). Niveau du set = plus haut niveau des pièces visibles (badge à côté du nom en Minimal compact/déployé, Line, Full ; lecture seule en édition). Catalogue : slider niveau + slider nb de pièces + menu types d’objets (sans pré-coche) + sélecteur de bonus (caractéristique puis min/max, somme des paliers) + pastilles d’état complètes ; tri défaut niveau croissant. Pièces en vue texte (`EntityViewTextLink` → `ItemViewMinimal`) ; le payload lecture/catalogue n’embarque que les pièces `visibleToUser` (+ `bonus`/`effect` pour le total). Bonus `{ "2": {…} }` : `PanoplyBonusTiers` — **une ligne par palier** (badge pièces + chips) en Minimal/Line ; **une colonne par palier** en Full (badge en tête, icon + nom). Minimal **déployé** : ligne **Total** = pièces + tous les paliers, sans badge de pièces (`combinedPanoplyEquipmentBonus`). Sur un **équipement** du set, `ItemPanoplyMark` (icône seule en minimal compact, icône+nom ailleurs, full = nom + pièces + colonnes de bonus ; payload serveur filtré `view`). Tooltip panoplie : mêmes vues texte (clic → popover Minimal). Édition : pièces puis bonus de set en tête de page (cartes `bg-base-100/30`) ; nom / droits en bas. Picker API + `PanoplyBonusEditor` (caractéristique + valeur par palier). Cartes Minimal : groupe Tailwind nommé `group/entity-minimal` (un survol ne déploie pas toute la grille).
- **Afficher (toutes entités)** : vue Minimal / Line / liste → modal full (`quick-view`). Page Show seulement depuis la modal (**Agrandir** / Ctrl+clic). Preset `minimalLine` sans `view`. Shell : `useEntityMinimalShell`. CMS : `SectionEntityTableRead`.
- **Créer (Index + bibliothèques CMS)** : `CreateEntityModal` (`entity-create-config.js`) — champs principaux seulement (`getEntityCreateCoreFieldKeys`) ; onglets **Conversion IA** / **JSON** si admin et type convertible (store JSON `{id,edit_url}` puis `ia-convert` ou `ia-inject`) ; après création, vue Modifier. Pas de bouton si `store` stub (`panoplies`, `shops`, `scenarios`).
- **Éditer (toutes entités)** : raccourci des options → page Modifier (`edit`). Header `EntityEditHeader` + `EntityEditForm` `layout-profile="sheet"` (2 cols ; dock masqué). Capacité : header + grille `capability`. Pas de modal ni panneau d’édition multiple. Sélection : cases toujours visibles en colonnes / Line ; en vue minimale, seulement sur la carte déployée (ou déjà cochée). `normalizeTableRowId`. Raccourcis tableau : `useTanStackTableKeyboard.js`.
- Chargement tableaux : vue colonnes = `TanStackTableSkeletonBody` (cellule image = vignette + 2 barres) ; Minimal / Line = `EntityViewSkeleton` (plusieurs cartes image+texte). Sections CMS : `SectionContentSkeleton` selon le template (`SectionLazyGate`, `SectionRenderer`, templates async).
- Caractéristiques runtime : `CharacteristicsCard` densités `icon|labeled|spacious`, groupes via `creatureCharacteristicGroups.manifest.js`, `CharacteristicGroup` (`levelEffective` → `runtime.levels`). Infobulle / popover joueur : `CharacteristicInfoPanel` (`useCharacteristicCard`, API `…/card`). Décomposition des couches uniquement dans le panneau MJ (`CharacteristicGmPanel` → `CharacteristicDecompositionBody`). Édition : `CharacteristicGmButton` (group/entity séparés).
